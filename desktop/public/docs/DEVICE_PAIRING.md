# جفت‌سازی دستگاه — DEVICE_PAIRING

وضعیت: **در دسترس نیست.**

هیچ همگام‌سازی بین Android و Omni Desktop، کشف دستگاه در شبکه، جفت‌سازی QR، انتقال حافظه یا اجرای ابزار از راه دور در این نسخه وجود ندارد. endpoint‌های `/profile`، TLS و token rotation نیز پیاده‌سازی نشده‌اند.

## هدف

جفت‌سازی امن یک دستگاه Android با نسخهٔ دسکتاپ در همان شبکهٔ محلی، با کمترین اعتماد پیش‌فرض و امکان لغو فوری.

## مدل تهدید

- شبکهٔ محلی ممکن است غیرقابل‌اعتماد باشد.
- مهاجم می‌تواند پیام‌ها را ببیند، تغییر دهد یا دوباره بفرستد.
- کد QR ممکن است عکس گرفته شود؛ بنابراین عمر کوتاه و استفادهٔ یک‌باره لازم است.
- هیچ کلید خصوصی نباید از دستگاه خارج شود.

## پیش‌نویس پروتکل

1. **کشف**: دسکتاپ یک سرویس loopback/LAN با شناسهٔ تصادفی اعلام می‌کند. (پیاده‌سازی نشده)
2. **QR**: دسکتاپ یک payload کوتاه‌عمر می‌سازد:

```json
{
  "v": 1,
  "endpoint": "https://192.168.1.10:4318",
  "deviceId": "uuid",
  "publicKey": "base64url",
  "nonce": "base64url",
  "expiresAt": 0
}
```

3. **تأیید**: موبایل nonce را امضا می‌کند و کلید عمومی خود را می‌فرستد؛ دسکتاپ امضا را بررسی و یک session token کوتاه‌عمر صادر می‌کند.
4. **نشست**: هر درخواست با token و امضای درخواست محافظت می‌شود. token قابل‌لغو و دارای scope است.
5. **چرخش**: tokenها عمر محدود دارند و بدون نیاز به جفت‌سازی مجدد چرخش می‌کنند. (پیاده‌سازی نشده)

## scopeهای پیشنهادی

- `chat.read` — خواندن گفت‌وگوها
- `chat.write` — ارسال پیام
- `memory.read` — خواندن حافظهٔ انتخاب‌شده
- `memory.write` — افزودن/حذف حافظه
- `device.status` — وضعیت باتری/شبکه (فقط با اجازهٔ صریح)

اجرای ابزارهای دستگاه (`tools.invoke`) در V1 وجود ندارد و نباید بدون تأیید جداگانه اضافه شود.

## الزامات امنیتی

- TLS با گواهی محلی معتبر؛ HTTP ساده فقط روی loopback.
- کد QR یک‌بارمصرف و حداکثر ۶۰ ثانیه معتبر.
- مقایسهٔ امضا با زمان ثابت.
- rate limit و قفل پس از تلاش‌های ناموفق.
- نمایش دستگاه‌های جفت‌شده و دکمهٔ «لغو دسترسی» در Settings.
- حذف کامل کلیدها هنگام unpair.
